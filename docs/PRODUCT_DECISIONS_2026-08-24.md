# VoxLocal 产品与技术决策（2026-08-24）

本文整理本轮讨论中已经明确的产品方向、能力边界和实现顺序，作为后续开发、Agent 接入和发布验收的共同基线。

## 1. 核心结论

VoxLocal 的目标不是把模型、分片、运行时和设备参数暴露给普通用户，而是提供一条尽可能短的内容生产路径：

1. 用户录制并授权自己的声音，或选择公共音色。
2. 用户输入文字、打开文档，或者由 Codex 等 Agent 生成内容。
3. 点击一次生成完整音频。
4. 可选维护一张人物照片，将完整音频进一步生成讲述视频。

底层可以复杂，但产品界面必须简单。模型下载、设备判断、任务分片、缓存命中、失败回退和文件拼接都应由后台完成。

## 2. Codex 与声音引擎的边界

Codex 是内容理解和任务调度层，不是底层声音合成器。它可以：

- 生成、整理或读取文本；
- 根据用户偏好选择音色与参数；
- 调用 VoxLocal 生成声音；
- 等待任务完成并取得音频文件；
- 将音频继续交给视频引擎；
- 返回文件位置、播放结果和失败原因。

真正把文字变成声音或复制音色，必须由一个实际声音引擎完成：

```text
用户 / Codex
    ↓
VoxLocal 统一任务接口
    ↓
本地声音引擎 / 云端自定义音色 / macOS 系统音色
    ↓
完整音频文件
    ↓（可选）
照片视频 / 口型同步引擎
    ↓
MP4 视频
```

因此，即使设备没有本地模型能力，也不是由 Codex 自身“直接克隆”，而是由 Codex 调用可用的云端声音服务。若本地和云端自定义音色都不可用，则回退到公共音色或系统音色。

## 3. 三类声音能力

| 模式 | 适用场景 | 优点 | 限制 |
| --- | --- | --- | --- |
| 本地克隆 | Apple Silicon、有足够磁盘与内存、重视隐私 | 离线、素材不上传、可控 | 首次下载较大，推理速度受设备影响 |
| 云端自定义音色 | 本地设备能力不足、允许联网 | 本地负担小、接入流程较短 | 需要 API Key、账号权限、网络和明确授权 |
| 公共/系统音色 | 无克隆条件或希望立即使用 | 开箱即用、风险低 | 不是用户本人的音色 |

推荐的产品配置只有三个选项：

- `自动选择`：优先采用用户允许且已经就绪的引擎，失败时按策略回退。
- `完全本地`：禁止上传声音与文档，只使用本地模型或系统音色。
- `云端优先`：允许使用已配置的云端自定义音色服务。

自动选择不等于静默上传。首次启用云端前必须明确告知上传内容、用途和数据边界，并取得用户确认。

OpenAI 官方 API 已提供自定义音色相关接口，但创建音色需要声音样本和单独的授权录音，并且只对符合条件的客户开放。参考：[OpenAI Create voice API](https://developers.openai.com/api/reference/resources/audio/subresources/voices/methods/create)。

## 4. 音色录制与授权

克隆音色必须满足以下原则：

- 默认只允许用户克隆自己的声音，或具有明确授权的声音。
- 录制界面使用随机参考文本，降低固定样本带来的过拟合和滥用风险。
- 录制完成后可试听、废弃、降噪优化并查看处理进度。
- 克隆音色与公共音色分区展示，可喜欢、置顶、拖拽排序和删除。
- 删除先进入回收站，清空回收站后才永久删除文件。
- 本地音色的参考录音、参考文字和音色信息必须持久化，应用重启后仍可使用。

## 5. 生成与播放必须分离

“生成文件”和“播放文件”是两套状态：

- 生成负责产出完整音频并保存历史。
- 播放只读取已存在的缓存或历史文件，不应该重复调用模型。
- 同一音色与同一试听文本应命中同一个缓存文件。
- 切换音色不会自动朗读；只有用户点击播放才开始。
- 同一时间只能有一个试听或正文播放器发声，新播放会停止旧播放。
- 生成历史只展示用户主动生成的资源；系统试听缓存单独存放。

长文本由后台分片生成后无缝拼接为一个完整文件。用户不需要理解“多少字一片”，只需要看到清晰的阶段、百分比、取消和失败原因。

## 6. 单照片 + 声音视频

视频能力作为独立一级菜单存在，不与阅读页面混杂。

### 用户流程

1. 维护一张启用中的人物照片，可替换或删除。
2. 从 VoxLocal 生成历史选择完整音频，或导入 WAV、MP3、M4A、AAC。
3. 选择合成方式。
4. 点击生成，查看进度。
5. 在应用内播放 MP4，或在 Finder 中定位。

### 两种合成方式

- `基础合成`：静态照片与完整音频封装为标准 MP4。它是稳定回退通道。
- `口型同步`：使用 Wav2Lip 或其他可替换引擎，让照片嘴型跟随声音。

Wav2Lip 适合作为第一版适配器，但不是永久绑定。其官方公开代码和权重受数据集许可影响，仅适用于个人、研究和非商业用途；商业发布前必须更换为获得商业许可的模型或服务。

单张照片的 Wav2Lip 主要改变嘴部区域，并不会自然生成完整的头部动作和眼神变化。界面和宣传不得把它描述成完整数字人。

## 7. 可插拔架构

声音与视频都采用适配器接口，不让 UI 直接依赖某个模型：

```text
SpeechEngine
├── MacSystemSpeech
├── Qwen3TTSLocal
├── KokoroLocal
└── CloudCustomVoice（可选）

VideoEngine
├── StillPhotoVideo
├── Wav2Lip（可选、非商用提示）
└── LicensedLipSyncEngine（后续）
```

统一任务应包含：任务标识、引擎、输入资源、阶段、进度、输出路径、错误、创建时间和幂等键。桌面界面、Codex 插件、WorkBuddy 和其他 MCP 客户端复用同一份任务语义与本地资源目录。

## 8. 设备与故障回退

VoxLocal 以 Mac 为主，并按设备动态选择模型、分片和并发。产品层不展示复杂硬件参数，只展示“可用、需要安装、正在准备、空间不足或不可用”。

建议回退顺序由用户的隐私模式决定：

- 完全本地：本地克隆 → 本地公共音色 → macOS 系统音色。
- 自动选择：已就绪的授权自定义音色 → 本地公共音色 → 系统音色。
- 云端优先：云端授权音色 → 本地克隆 → 公共音色。

任何回退导致音色发生变化时都必须提示用户，不能悄悄用另一种声音生成正式内容。

## 9. 数据、安全与许可

- 本地模式下，文档、录音、模型、音频和视频只保存在 VoxLocal 应用数据目录。
- 前端只能读取已经登记的照片、音频和视频，不能利用路径参数访问任意本地文件。
- 文件导入需要校验扩展名、文件头、大小和实际存在性。
- 子进程调用使用参数数组，不拼接 Shell 字符串。
- 云端密钥保存在系统安全存储，不写入仓库、日志或普通配置文件。
- 上传云端前显示明确同意；用户可以全局关闭云端能力。
- 公共音色、克隆模型和视频模型必须在资源清单中记录来源、许可证、大小、用途和下载方式。

## 10. 实施顺序

1. 保持现有本地朗读、音色克隆、缓存和历史稳定。
2. 完成独立“照片 + 声音”视频页面和基础 MP4 合成。
3. 接入 Wav2Lip 可选适配器，明确许可并按需安装。
4. 把“生成声音 → 生成视频”组合任务暴露给 MCP/Codex。
5. 增加云端声音适配器，但仅在确认目标账号具备自定义音色权限后启用。
6. 商业发布前完成模型许可审查，并替换不适合商业用途的口型引擎。

## 11. 最终产品原则

> 用户只需要决定“用什么内容、什么声音、要不要视频”；引擎、设备和任务细节由 VoxLocal 自动处理。

所有后续功能都应以这条原则评估：如果一个底层概念不是用户完成任务所必需，就不应该出现在默认界面中。
